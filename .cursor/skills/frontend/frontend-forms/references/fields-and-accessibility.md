# Поля и доступность

Читай, когда нужны label, связь с контролом, ошибки для AT, focus, checkbox/radio/select/file. Стек — [discovery-and-stack.md](discovery-and-stack.md). Submit и массивы — [lifecycle-and-submit.md](lifecycle-and-submit.md). Визуальная сетка подписи и контрола — `frontend-layout`; здесь — поведение и a11y формы. Системный a11y/WCAG-аудит («проверь доступность», не реализация формы) — [`frontend-a11y`](../../frontend-a11y/SKILL.md).

Примитивы зоны переиспользуй, параллельный кит не заводи. Их локальные дыры **не копируй** (§6).

## 1. Имя поля: label + `htmlFor` + `id`

У каждого видимого контрола есть доступное имя.

- Стабильный уникальный `id` на **input/select/textarea** (или на виджет, который его прокидывает). Для повторяемого React-компонента используй `useId()` или уникальный instance-prefix из props, не строковую константу на все экземпляры.
- `<label htmlFor={тотЖеId}>`. Не `htmlFor={name}`: имя поля RHF/Formik (`email`, `taskStructures.0.title`) — не id в DOM и часто невалидный/нестабильный селектор.
- Не заменяй label атрибутом `placeholder`. Placeholder — подсказка формата, не имя.
- Группа radio — `fieldset`/`legend` (или принятый в зоне эквивалент), у каждой опции свой label.

Визуальная подпись рядом (`Text`, `span`, `FormField`) **не** связана с контролом, пока нет `htmlFor`/`id`, обёртки `<label>` вокруг контрола или `aria-labelledby` на тот же элемент. Если layout-примитив рисует только `Text`, имя всё равно задай на контроле (`label`+`id`, `aria-label` с тем же текстом, скрытый `<label>`).

## 2. Ошибка: `aria-invalid`, `aria-describedby`, объявление

| Состояние | Что выставить |
| --- | --- |
| Поле с ошибкой | `aria-invalid={true}` (или принятый проп виджета, который это делает) |
| Текст ошибки | свой `id`; контрол: `aria-describedby` на этот id (+ id подсказки, если она есть) |
| Нет ошибки | не оставляй `aria-invalid="true"`; не ссылайся на несуществующий id ошибки |

Текст ошибки должен быть в DOM, когда поле невалидно — не только цвет рамки и не только toast. Для AT этого достаточно; отдельный `role="alert"` на каждую ошибку не обязателен, если в зоне уже объявляют через связанный текст. Не молчи про ошибку, показывая лишь `toast`.

## 3. Focus первой ошибки

После неуспешного submit фокус уходит в **первый невалидный input**, не на кнопку и не в пустоту.

Нужен рабочий `ref` на DOM-контрол:

- RHF: не отбрасывай `field.ref` / `register().ref`; штатный `shouldFocusError` и явный `setFocus` работают только если ref дошёл до input. Не ищи nested path через сырой `Object.keys(errors)[0]`.
- Formik: сохрани ref на поля или используй уже принятый в зоне способ; `innerRef` не выкидывай. Для nested errors используй явный порядок field paths, не сырой верхнеуровневый ключ.
- native: `ref` на input + `focus()` по первому ключу в словаре ошибок.

Кастомный виджет (`forwardRef` / `slotProps.inputRef`) обязан прокинуть ref в настоящий `<input>`. Обёртка с `role="button"` вокруг input не заменяет фокус на сам input.

## 4. Controlled / uncontrolled и состояния

Значение поля живёт в form state трека. Не держи параллельный `useState` на то же значение (исключение — локальный preview файла, §5).

| Виджет | Binding |
| --- | --- |
| text / textarea | `value` + `onChange` (controlled) **или** `register` без дубля state |
| checkbox | `checked` + `onChange`, не `value={boolean}` как у текста |
| radio | одно имя группы, `checked` по значению формы |
| select | `value` / `onChange` как у соседей; пустая опция — валидный пустой form value |
| file | файл в form state через `setValue` / `Field`; `value` у `<input type="file">` не контролируй строкой |

`disabled` — поле не в фокусе и не попадает в нативный `FormData`; конкретная form library может хранить или исключать его значение по своим правилам, поэтому проверь API выбранного трека. `readOnly` — ещё в табе и нативных данных. Не подменяй одно другим без причины. Кнопку submit на время мутации дизейбли — [lifecycle-and-submit.md](lifecycle-and-submit.md).

Не логируй значения полей.

## 5. Файл и preview

Локальный preview в `useState` допустим. В form state хранится значение по контракту зоны: `File`/`FileList`, результат upload-first (`assetId`/URL) или пустое значение после удаления — не только preview. Не дублируй **всю** форму в `useState` ради картинки.

XSS/unsafe preview содержимого поля — `frontend-security`, не этот файл.

## 6. Anti-patterns локальных примитивов — не копировать

Reuse form-примитивов зоны не означает, что их семантику нельзя проверить. Не заводи второй кит, но при правке примитива или новой обвязке не закрепляй следующие дыры.

### Обвязка отбрасывает `ref`

Если controller деструктурирует `field: { ref, ...fieldProps }`, а в control передаёт только `fieldProps`, штатный focus ошибки и явный `setFocus` не попадут в input.

Как надо: прокидывать `ref` в контрол (`{...field}` целиком или `ref` отдельным аргументом). Как не надо: деструктурировать `ref` и забыть.

`htmlFor={name}` на `<label>` не исправляет это автоматически: `name` поля ≠ гарантированно уникальный `id` контрола. Input внутри children должен получить тот же `id`.

### Визуальная подпись не связана с контролом

Заголовок через `Text`/`span` — визуальная колонка (layout), не accessible name без `label`/`aria-labelledby`.

Как надо: на самом контроле — `id` + label/`aria-label`/`aria-labelledby` с тем же текстом. Как не надо: считать, что соседний `Text` уже сделал label.

### Placeholder вместо имени

Не оставляй поле только с `placeholder`, даже если макет «без подписи». Подпись может быть визуально скрыта, но не отсутствовать для AT.
