# Семантика и accessible names

Читай на шаге 3, когда нужны landmarks, headings, native semantics, имена, изображения, таблицы/списки. Клавиатура и live regions — [keyboard-focus-and-dynamics.md](keyboard-focus-and-dynamics.md). Пары Плохо / Хорошо — [examples-good-and-bad.md](examples-good-and-bad.md).

Hit-area и токены фокуса при вёрстке — [`pravila.md`](../../frontend-layout/references/pravila.md) §6, не этот файл.

## 1. Landmarks и headings

Страница (или независимый экран SPA) должна давать AT каркас, а не «стену `div`».

- Один основной регион содержимого: `<main>` или принятый примитив зоны с той же ролью. Второй `main` на том же экране — finding.
- Повторяемая навигация — `<nav>` (или эквивалент зоны) с различимым именем, если нав больше одной.
- Баннер / контентинфо — `<header>` / `<footer>` страницы, не каждая карточка.
- Заголовки идут по смыслу: один `h1` экрана (или принятый паттерн зоны), дальше без скачков `h1` → `h4`. Пропущенный уровень сам по себе не всегда `FAIL`; пустой экран без заголовка при наличии самостоятельного содержимого — да.
- Не ставь `role="main"` на `div`, если можно `<main>`. Не объявляй `role="navigation"` на `<nav>`.

iframe / вложенное приложение в scope — отдельный документ: свои landmarks, не «ещё один `main` снаружи».

## 2. Native-first: кнопка, ссылка, не-интерактив

Роль должна совпадать с поведением.

| Поведение | Нативный элемент | Не замена |
| --- | --- | --- |
| Действие на этой странице | `<button type="button">` или примитив `Button` зоны | `div`/`span` + `onClick` / `role="button"` |
| Переход к ресурсу / маршруту | `<a href>` или примитив `Link` зоны | `button` + `navigate` без причины; `div` + роутер |
| Раскрытие панели | `<button>` + состояние (см. examples) | заголовок/`div` только с кликом |
| Текст, декорация | элемент без интерактивной роли | кликабельный текст без роли и tabindex |

`href` пустой, `#` без цели или `javascript:` — это не ссылка. Кнопка без `type` внутри `<form>` может сабмитить: в аудите отметь, если это не submit.

`role="button"` / `role="link"` на `div` не закрывает находку: нет клавиатурного контракта, нет default AT-поведения. В `fix` замени элементом, не дорисуй ARIA. См. [examples-good-and-bad.md](examples-good-and-bad.md) §1.

## 3. Accessible name

У каждого интерактивного контрола есть имя, которое AT может произнести. Источник имени укажи в evidence (не значение, если это PII — `[REDACTED]`).

Порядок проверки (платформа, не фреймворк):

1. связанный `<label>` / `<caption>` / `<th>` / текст ссылки или кнопки;
2. `aria-labelledby` на видимый элемент;
3. `aria-label`;
4. `alt` у изображения-контрола;
5. `title` — последний и слабый; не считай его достаточным именем кнопки.

Пустое имя: иконка-кнопка без текста и без `aria-label` / `aria-labelledby`; ссылка «подробнее» без отличимого контекста, если рядом несколько одинаковых. Декоративная иконка **внутри** именованной кнопки — `aria-hidden="true"` (или `alt=""` у img), чтобы имя не дублировалось. См. examples §2 и §7.

Не подменяй видимый текст скрытым `aria-label` с другим смыслом: зритель и AT должны получить одно действие.

`aria-labelledby` на несуществующий id — имени нет. Не собирай имя из unsanitized HTML: это hand-off в [`frontend-security`](../../frontend-security/SKILL.md).

## 4. Изображения

| Вид | Имя |
| --- | --- |
| Содержательное (график, фото с смыслом, иконка-единственный контент ссылки) | Короткий `alt` / текстовая альтернатива, что изображение **делает** на экране |
| Декоративное (повтор иконки рядом с текстом, фон) | `alt=""` или `aria-hidden` на декоративном узле; не `alt="icon"` / имя файла |
| Сложное (схема, канвас) | Короткий `alt` + длинное описание рядом (видимый текст или связанный id) |

`alt="image"`, `alt="picture"`, `alt="img_12"` — не имя. Отсутствие `alt` у `<img>` — confirmed, если узел в проде. CSS `background-image` с смыслом без текста в DOM — finding; чисто декоративный фон — не finding.

## 5. Таблицы и списки

Данные с рядами/колонками — `<table>` + `<th>` (и `scope` / `<caption>`, если без них заголовки неоднозначны). Сетка из `div` с «ячейками» только стилями — не таблица для AT. См. examples §8.

Список ссылок или шагов — `<ul>`/`<ol>`, не набор абзацев, если порядок или группировка важны. Не ставь `role="list"` на `<ul>`.

Layout-таблица (редкий легаси) не выдавай за data table: если нет заголовков данных — это вёрстка, отдай визуал в layout, здесь отметь только если AT слышит ложную таблицу.

## 6. Form-поля: только дельта аудита

Не копируй рецепты `htmlFor` / `useId` / `ref` / `aria-invalid` / focus первой ошибки. При **системном** a11y-запросе проверь факты:

- у видимого контрола есть accessible name (не один `placeholder`);
- ошибка, если показана, связана с контролом или объявлена, а не только цветом рамки;
- кастомный виджет не отрезает фокус от настоящего input.

Как **сделать** связь label/id, `aria-describedby` и focus первой ошибки — [`fields-and-accessibility.md`](../../frontend-forms/references/fields-and-accessibility.md). При реализации формы ведёт `frontend-forms`. Сетку подписи — `frontend-layout`.

Находка «нет имени у поля» — a11y finding с `file:line`. Находка «не тот binding RHF/Formik» — не этот файл.

## 7. ARIA — только если нативного не хватает

Сначала элемент и атрибуты платформы, потом роль. Не добавляй `aria-*` «на всякий случай».

Запрещено как fix: `role="button"` вместо `<button>`; дублировать implicit role (`<button role="button">`); `aria-hidden="true"` на фокусируемом контроле; скрывать видимый лейбл и оставлять другое `aria-label`.

Виджеты (tabs, menu, combobox) — роли и связи только если набора native элементов недостаточно **и** в зоне нет готового примитива. Клавиатурный контракт виджета — [keyboard-focus-and-dynamics.md](keyboard-focus-and-dynamics.md).
