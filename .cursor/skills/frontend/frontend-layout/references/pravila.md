# Общие правила вёрстки

Стек-агностичные правила. Читай **до** файла трека (Modules, Tailwind, CSS-in-JS, SCSS, UI-kit) — и даже если отдельного трека нет. Конкретный синтаксис (компонент ряда vs `display: flex` vs `flex gap-4` vs `sx` vs `styled`) — из ближайших файлов репозитория, не из привычки модели.

Не добавляй логирование в вёрстку и в примеры кода.

## 1. Макро обычно Grid, микро обычно Flex

| Задача | Инструмент |
| --- | --- |
| 2D: сетка карточек, дашборд, страница с колонками, форма с несколькими осями | **Grid** |
| 1D: тулбар, кнопка+иконка, ряд фильтров, колонка полей, header | **Flex** |

Это default, не запрет: wrapping-ряд карточек может остаться Flex, если так устроены ближайшие компоненты и независимые колонки не нужны. Не решай двумерную раскладку тройным вложенным Flex. Не решай «иконка рядом с текстом» через Grid.

Как именно писать Grid/Flex — как у соседей: примитив, утилита, `display` в CSS, `sx`, styled.

## 2. Ритм через `gap` и padding контейнера

Отступы между соседями — `gap` на родителе. Внутренний воздух — `padding` контейнера (карточка, секция, ячейка).

Не используй `margin-right` / `margin-bottom` на каждом ребёнке и хаки `:last-child { margin: 0 }`. `margin-inline-start: auto`, типографический поток и осознанный overlap — отдельные случаи, их не заменяй `gap` механически. Не схлопывай ритм отрицательными margin без явной причины.

```tsx
// надо — gap на родителе
<Parent gap>
  <Child />
  <Child />
</Parent>

// не надо
<Child style={{ marginRight: 16 }} />
<Child style={{ marginRight: 16 }} />
<Child />
```

Шкала spacing — из проекта (токены, theme, шкала примитива), не случайные `13px` / `17px`.

## 3. Токены для цвета и типографики

Цвет, фон, `font-size`, `font-weight`, `font-family` — из дизайн-токенов проекта, не сырой hex / произвольный px.

Откуда брать — смотри соседей:

- CSS-переменные `var(--*)`
- theme Tailwind / `@theme`
- тема UI-кита (MUI palette, Ant token, styled theme)
- объект темы / design tokens в коде

Типографика — через текстовый примитив проекта, если он есть; иначе шкала theme / токены, не локальный `font-size: 20px` в новом файле.

## 4. Flex-дети с длинным текстом: `min-width: 0`

В строке Flex дети по умолчанию не сжимаются ниже `min-content`. Длинный заголовок, путь, email — ставь `min-width: 0` (и при необходимости `overflow: hidden` / `text-overflow: ellipsis` / проп обрезки у текстового примитива).

Иначе ряд раздувает контейнер и ломает таблицу, карточку, тулбар.

## 5. Визуальный порядок = DOM

Порядок в разметке — тот же, что видит пользователь и что читает скринридер / Tab.

Не используй `order`, `row-reverse`, `column-reverse` для интерактивных рядов (кнопки, ссылки, поля), чтобы «просто переставить». Reverse у примитива — только если в проекте уже так сделано и это не ломает фокус.

## 6. Hit-area, focus, семантика

- Кликабельное — `<button>` / `<a>` / существующий `Button` проекта, не `div` с `onClick`.
- Иконка-кнопка: достаточная область нажатия (ориентир ≥ 24–32px), не «иконка 12px без padding».
- Фокус видимый: токены проекта, не `outline: none` без замены.
- Интерактив доступен с клавиатуры; drawer / modal сохраняет ожидаемый focus flow и закрывается как соседние компоненты.
- Смысл и состояние не передаются только цветом; контраст — не хуже существующих токенов и компонентов проекта.
- Лендмарк страницы: один `main` (через примитив проекта, если он так умеет).
- Подписи полей через существующий Form-примитив / `label`, не placeholder вместо label.
- Новая необязательная анимация учитывает `prefers-reduced-motion`, если в проекте ещё нет общей абстракции для этого.

Системный a11y/WCAG-аудит — [`frontend-a11y`](../../frontend-a11y/SKILL.md); hit-area, видимый focus и DOM-порядок при вёрстке остаются здесь.

## 7. Адаптив проекта, не универсальный «mobile-first наугад»

Сначала брейкпоинты и хуки **этого** репозитория. Не вводи дефолты чужого фреймворка, если в соседних файлах уже другие числа.

Container queries — только если в репозитории уже есть прецедент или пользователь явно просил. Не канонизируй компоненты, которые страницы не импортируют.

## 8. Не подменяй стек

- Нет Tailwind — **не** добавляй `tailwind.config`, `@tailwind`, утилитарные `className="flex gap-4"`.
- Нет CSS Modules — **не** заводи `*.module.css` «по привычке».
- Нет styled-components / Emotion / MUI / Ant — **не** ставь пакет и не пиши `styled.div` / `sx` «как привычнее».
- Уже утилиты — не заводи module, пока задача не требует анимации / сложного селектора.
- Уже CSS-in-JS / `sx` / SCSS — пиши так же, не переводи файл на Modules или Tailwind.
- Hybrid (Modules + Tailwind в одном репо): layout и spacing утилитами, сложные селекторы и keyframes — в module. Не мешай оба на одном узле без причины.

## Чеклист (общее)

- [ ] 2D — Grid, 1D — Flex
- [ ] Ритм через `gap` + padding, не margin-соседи
- [ ] Цвет и типографика из токенов
- [ ] Длинный текст в Flex не раздувает ряд (`min-width: 0`)
- [ ] DOM-порядок = визуальный порядок
- [ ] Семантика, hit-area, видимый focus
- [ ] Брейкпоинты проекта
- [ ] Стек репозитория не подменён чужим
