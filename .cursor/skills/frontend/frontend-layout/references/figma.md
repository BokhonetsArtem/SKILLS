# Режим макета: Figma MCP / Bridge

Читай этот файл целиком, когда вход — Figma URL, node id, выделенный фрейм или явное «по макету».

Не добавляй логирование в вёрстку и в примеры. Не правь файл в Figma: этот скил только читает макет и верстает в коде.

## 0. Discovery до любого вызова

MCP-инструменты **нельзя** вызывать по памяти. Схема живая — её читают каждый раз.

1. `GetDynamicTools` с `namespace` (см. таблицу ниже). Можно параллельно по обоим namespace.
2. Смотри `namespaceStatus` и список `tools`.
3. Если `namespaceStatus` = `needsAuth` **или** вызов вернул ошибку auth — `CallDynamicTool` с `toolName: "mcp_auth"` и пустыми `arguments: {}` для этого namespace. Затем снова `GetDynamicTools`.
4. Перед каждым вызовом прочитай схему нужного инструмента (`GetDynamicTools` с `namespace` + `toolName`, либо запись из шага 1). Аргументы — только из схемы, не из этого файла.
5. Вызов: `CallDynamicTool` (`namespace`, `toolName`, `arguments` по схеме). Для внешних MCP передай `mcpDetails.description` — одно короткое предложение, что получишь и к чему это (фрейм, страница, файл).

Имена namespace в этой сессии:

| Источник | `namespace` |
| --- | --- |
| Framelink | `user-Framelink MCP for Figma` |
| Bridge | `user-figma-bridge` |

Если точное имя не находится — `GetDynamicTools` с `pattern` вроде `figma|Framelink|bridge`. Не выдумывай namespace.

## 1. Нет MCP → текстовый режим

Текстовый режим (верстай по описанию задачи и паттернам проекта, **не** подставляй сетку/отступы/цвета «как в макете»):

- нужного namespace нет в каталоге;
- `namespaceStatus` — `needsAuth` / `error` / `loading`, и `mcp_auth` не помог;
- в namespace нет инструментов из таблицы ниже;
- пользователь дал URL, но `fileKey` не извлечь, а Bridge не подключён.

Скажи, что макет недоступен. Продолжай в текстовом режиме, только если текст задачи, вложения или существующие экраны дают достаточно данных. Если вход — только недоступный URL или без макета нельзя выполнить ключевые требования, запроси скриншот / экспорт / описание вместо того, чтобы выдумывать UI.

## 2. Что чем вызывать

| Задача | Где | Инструмент |
| --- | --- | --- |
| Структура, layout, контент, компоненты по URL | Framelink | `get_figma_data` |
| Иконки, иллюстрации, растр на диск | Framelink | `download_figma_images` |
| Дерево текущего выделения / страницы | Bridge | `get_design_context` |
| Сверка с картинкой макета | Bridge | `get_screenshot` |
| Токены Figma (цвета, числа, строки) | Bridge | `get_variable_defs` |
| Локальные стили документа | Bridge | `get_styles` |
| Сохранить PNG / SVG / JPG / PDF на диск | Bridge | `save_screenshots` |
| Логин | оба | `mcp_auth` |

**URL → Framelink.** Из `figma.com/design/<fileKey>/…` или `figma.com/file/<fileKey>/…` возьми `fileKey`. `node-id=1234-5678` → `1234:5678` (дефис в id узла замени на `:`). `nodeId` передавай всегда, если он есть в URL. `depth` у `get_figma_data` **не** ставь, пока пользователь явно не попросил.

**Выделение в десктопе / плагин → Bridge.** `get_design_context` ходит в текущий selection (или страницу). Несколько файлов — сначала `list_files`, дальше `fileKey` в остальные вызовы. Id узлов в Bridge — только двоеточия (`4029:12345`, инстанс `I12740:17806;12740:17793`), **не** дефисы.

Оба доступны — можно вместе: Framelink по URL (данные + ассеты), Bridge — скрин и переменные. Не дублируй один и тот же гигантский dump без нужды.

Не вызывай инструменты Bridge, которые изменяют документ Figma (`create_frame`, `set_text_content`, `delete_nodes` и т.п.). `save_screenshots` пишет экспорт на локальный диск и допустим для ассетов.

## 3. Порядок работы

1. Discovery (раздел 0). Auth при необходимости.
2. Снять структуру: Framelink `get_figma_data` и/или Bridge `get_design_context`.
3. Токены и стили, если Bridge есть: `get_variable_defs`, `get_styles`. Сверь с токенами репозитория (как их уже импортируют соседи: `var(--*)`, `@theme`, тема кита — не угадывай).
4. Скрин для сверки: Bridge `get_screenshot` (по умолчанию PNG, scale 2). Нет Bridge — ориентируйся на визуалы из Framelink, не рисуй макет сам.
5. Скачай ассеты (раздел 6).
6. Определи стек (`SKILL.md` шаг 2) и верстай по треку: Auto Layout → Flex/Grid, hex → токены, компоненты Figma → примитивы проекта.
7. Сверь вёрстку со скрином и в браузере (чеклист `SKILL.md`).

## 4. Код из MCP — reference, не копипаста

Ответ MCP часто выглядит как готовый React + Tailwind (`className="flex gap-4 text-[#400799]"`). Это **подсказка** по иерархии, ритму и слоям, не файл в репозиторий.

- Стек репозитория (шаг 2 `SKILL.md`): перенеси структуру на примитивы и синтаксис **этого** репо. Классы Tailwind из MCP вставляй только если Tailwind уже стек.
- Имена слоёв Figma (`Frame 1328`, `Group 4`) не копируй в DOM. Семантика: `main`, `header`, список, кнопка.
- Абсолютный pin из Figma (`position: absolute` на всём экране) не переноси, если это обычный поток. Absolute — оверлей, бейдж, декоративное пятно.

```tsx
// не надо — выхлоп MCP как есть
<div className="flex flex-col gap-[24px] text-[#400799] text-[20px]">
  <span>Пользователи</span>
</div>
```

Если в репо есть `Flex`/`Text`/токены — иерархия на примитивы и токены, не утилиты из MCP. В другом стеке — та же иерархия, синтаксис соседей.

## 5. Hex → токены, Auto Layout → Flex/Grid трека

| В макете | В коде |
| --- | --- |
| fill / stroke hex, rgba | ближайший токен проекта (`var(--color-*)`, theme, palette кита), не `#400799` в CSS/утилите |
| font-size / weight / family | текстовый примитив проекта или шкала theme |
| Auto Layout горизонтальный/вертикальный + gap | 1D: layout-примитив с `gap` или flex/grid синтаксисом стека |
| Сетка карточек, колонки страницы, 2D | Grid синтаксисом стека |
| padding фрейма | padding контейнера (карточка, секция), не margin на каждом ребёнке |
| item spacing | `gap`, не `margin-right` |
| hug / fill | `width: fit-content` / `flex: 1` + `min-width: 0` у текстовых детей |

Нет точного токена — возьми ближайший из палитры проекта, не заводи новый hex «как в макете». Нет близкого — спроси или положи в существующий файл токенов, не в компонент.

`get_variable_defs` / `get_styles` мапь на имена репозитория, не на имена коллекций Figma один в один (`Purple/700` → `--color-purple-700`, не новый `--Purple-700`).

## 6. Ассеты скачивать, не рисовать

Иконки, логотипы, иллюстрации, фото — с диска макета, не SVG «на глаз» и не `GenerateImage`.

**Framelink `download_figma_images`** (схему читай перед вызовом):

- обязательны `fileKey`, `nodes` (`nodeId` + `fileName` с расширением `png` \| `svg` \| `gif`), `localPath`;
- `imageRef` / `gifRef` — если они есть в данных узла;
- `localPath` — **из схемы инструмента**, не «от корня репозитория наугад». Часто это путь относительно image directory MCP, а не `src/shared/assets/…`. Цель — каталог ассетов **этого** проекта (часто `src/shared/assets/icons/` или `images/`, если так у соседей);
- после скачивания **проверь**, что файл появился внутри репозитория. Если MCP положил его вовне — перенеси в каталог ассетов проекта;
- `pngScale` по умолчанию 2.

**Bridge:** для просмотра используй `get_screenshot` — он возвращает base64. Для сохранения ассета на диск используй `save_screenshots`: `nodeId`, `outputPath` внутри каталога ассетов репозитория, `format: "SVG"` или PNG. Схему прочитай перед вызовом; относительный `outputPath` считается от cwd MCP-сервера, поэтому безопаснее передать проверенный абсолютный путь внутри репозитория. После вызова проверь, что файл появился в ожидаемом каталоге.

Имя файла — осмысленное kebab-case (`filter-icon.svg`), не `image-1.png`. Дальше — как в проекте: существующий способ импорта иконок. Не вшивай гигантский base64 в TSX.

## 7. Сверка

- До сдачи сравни вёрстку со скрином макета (иерархия, ритм, выравнивание), не только «похоже на Tailwind из MCP».
- Потом — браузер: клик, ввод, адаптив. Один скриншот кода недостаточен.
- Расхождение «пиксель в пиксель vs токен проекта» решай в пользу токена и примитивов.
